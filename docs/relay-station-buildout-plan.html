Relay Station · Build-out Plan

中转站从 0 到 1 搭建方案

面向 API 聚合网关（文本 / 图像 / 视频）的分阶段实施计划：主体资质、域名备案、服务器、支付接入、上游对接、号池搭建、试运行与验收，逐阶段列清我方交付物与需要客户配合的事项。

两条主线决定成败：「备案 + 支付」决定能不能合法收款；「上游对接 + 号池」决定有没有货可卖。两条线互不阻塞，必须并行推进——先做完一条再做另一条，周期会翻倍。

适用范围与前提

  • 本计划默认境内公司或个体工商户主体、服务器放在境内、对外经营收款。
  • 若为纯海外主体、仅自用不对外收款，第 1、2 阶段可大幅简化（免备案、可用境外服务器），整体周期可压到 2–3 周。
  • 若涉及「官网逆向 / 账号池」类上游，需额外评估合规与封号风险，见第 7 节。

03各阶段要做什么

每个阶段都写清了「我们做什么」和「需要你配合什么」——后者是进度最大变量。

P0

需求与合规评估

第 1 周 · 2–3 天

把「做什么、能做什么、边界在哪」定死，避免后面返工。

我方工作
  • 确认业务形态：面向 B 端还是 C 端、是否代充、按次还是包月
  • 梳理模型清单与优先级（文本 / 图片 / 视频），预估调用量
  • 合规评估：上游转售条款、经营性网站备案要求、是否需要增值电信业务许可
  • 输出《需求与合规确认单》，作为后续验收依据
交付物
  • 需求确认单（含模型清单与优先级）
  • 合规风险清单与红线说明
  • 排期初稿
需要客户配合
  • 明确目标客户群与月调用量预估（决定服务器规格与上游预充值额度）
  • 确认是否已有公司 / 个体工商户主体
  • 确认可接受的风险边界：是否接受官网逆向类上游、是否接受多上游冗余
阻塞风险：需求反复变更会直接推迟 P4 排期，建议本阶段一次性确认，后续变更走书面确认。
P1

主体资质 · 域名 · 备案 · 支付申请

第 1–4 周 · 关键路径

拿到能合法开站、能合法收款的「身份」。这一段是外部审核，最不可控。

我方工作
  • 营业执照办理指导（新办约 3–7 个工作日）
  • 域名注册与实名认证（1–3 天），.com / .cn 按品牌定
  • ICP 备案：接入商初审 1–2 天 → 管局审核 7–20 个工作日
  • 公安联网备案：网站开通后 30 日内完成
  • 支付申请：微信支付商户号、支付宝（电脑 / 手机网站支付），约 1–2 周
关键要求
  • 备案服务器必须在境内，备案期间域名不能解析到境外
  • 网站名称不得含「中国 / 国家 / 官方 / 政务」等敏感词
  • 主体信息、域名持有人、备案手机号三者必须一致
  • 个人主体基本无法申请商户支付，建议直接用企业或个体户
需要客户配合
  • 营业执照扫描件、法人身份证正反面、对公账户信息
  • 域名持有人实名信息（个人身份证或企业营业执照）
  • 备案手机号与邮箱，需能接收并即时回复核验短信 / 邮件
  • 网站名称与一句话简介（备案填写用）
交付物：ICP 备案号、公安备案号、支付商户号、可用的对公收款通道。阻塞风险：资料不齐或名称被驳回，每次重报 +1–2 周。
P2

服务器与基础环境

第 2–3 周 · 与 P1 并行

把地基打好：能跑网关、能存产物、能扛住视频流量。

我方工作
  • 云服务器选型（境内，4 核 8G 起；视频业务重点看带宽与流量包）
  • 系统初始化、容器运行时、PostgreSQL、Redis
  • 对象存储 + CDN（视频产物托管，避免占服务器带宽）
  • 域名解析、HTTPS 证书（自动续期）、反向代理
  • 数据库每日备份、可用性与错误率监控告警
交付物
  • 可访问的服务器环境与运维账号
  • 备份策略与监控看板
  • 环境说明文档（含回滚方式）
需要客户配合
  • 用客户自己的云账号实名购买（账号归属清晰，避免后期迁移与纠纷）
  • 确认服务器地域与规格档位（影响备案与访问速度）
  • 提供账号的运维子账号权限（不要给主账号密码）
提示：视频类业务的资源瓶颈是出流量，不是 CPU。选型时先算清单条视频的下载流量。
P3

网关部署与品牌化

第 3–5 周

把「能开站、能注册、能充值、能计费」这条最小闭环跑通。

我方工作
  • 部署 API 网关（new-api 类）：用户体系、令牌、分组、模型目录
  • 计费配置：分辨率 / 时长分档、按次与按秒口径分开核
  • 前台品牌化：站点名、Logo、接入教程页、客服入口、页脚主体信息
  • 充值体系：在线支付、兑换码、邀请返利（可选）
  • 风控：限流、IP 白名单、防刷、调用日志审计
交付物
  • 可对外访问的站点与后台
  • 面向下游的接入教程（接口、错误码、限流、退款规则）
  • 计费口径说明
需要客户配合
  • 品牌素材：站点名、Logo、主色、客服联系方式
  • 上架模型范围与默认规格档位确认
  • 客服话术与退款政策口径（避免下游争议时无据可依）
注意：前端展示价必须由后端价表驱动，不能前端写死，否则改价必然对不上账。
P4

上游对接

第 4–8 周 · 工作量最大

把「货」接进来，并逐模型核清上游口径，做到账实一致。

我方工作
  • 官方直连：OpenAI / Anthropic / Gemini / 豆包 / 通义 / 万相 / 可灵 等，企业认证 + 预充值
  • 二级供应商：对接、试用、约定对账口径与结算周期
  • 协议适配：OpenAI 兼容接口、异步任务（提交 / 轮询 / 取片）、参考图与参考视频、回调
  • 逐模型验收：每个上架模型跑 1 条真实任务，记录上游用量、计费口径、失败退款路径
  • 渠道冗余：同模型配 2 家以上上游，失败自动切换
交付物
  • 已上架模型清单（含规格与口径）
  • 逐模型用量台账
  • 渠道健康检查与自动切换策略
需要客户配合
  • 上游账号的企业实名 / 认证资料（部分平台必须企业主体）
  • 上游账号预充值（按量小额高频充，不要一次压大额）
  • 确认模型优先级：先上哪几个、哪些可以晚点
  • 是否接受「同一模型多家上游」的冗余方案
三个高频坑：① 按次与按秒口径不一致，导致账实不符；② 客户端取消但上游已出片，退款争议；③ 上游限流 / 封号无冗余，服务直接中断。
P5

号池搭建

第 5–8 周 · 视模式而定

把「多账号 / 多密钥」管起来，做到额度可控、失败可切、用量可查。

A · API Key 池（推荐起步）
  • 多供应商密钥分组，按权重 / 优先级轮询
  • 失败自动切换与熔断，避免单点打满
  • 额度监控与低余额告警
  • 按渠道归集用量，便于核对与容量规划
B · 官网账号池（仅在有独占能力时）
  • 账号采购与养号、单号日限额
  • 独立代理 IP、浏览器指纹隔离
  • 调度器派单、失败重试、封号补号
  • 产物回传与托管
需要客户配合
  • 号池账号数量与补号储备（视平台而定）
  • 代理 IP 资源（住宅 IP 与机房 IP 的可用性差异很大）
  • 书面确认是否接受官网逆向类上游的合规风险——封号与平台条款风险由业务方承担
现实提醒：官网账号池的隐性投入很高（养号、封号、改版适配），如果没有「只有官网才有」的独占模型，优先用 API Key 池。
P6

试运行与验收

第 8–10 周

先小范围跑通，账对得上，再放量。

我方工作
  • 灰度：内部账号 → 5–10 个种子客户 → 全量开放
  • 对账：上游用量记录 vs 本站流水，逐笔差异排查
  • 压测与故障演练：渠道下线、上游 429、缓存故障
  • 交付文档：接入教程、错误码、退款规则、SLA、应急联系人
交付物
  • 试运行报告（含对账差异与处理）
  • 运维手册与应急预案
  • 正式验收单
需要客户配合
  • 种子客户名单（真实使用场景比自测更有价值）
  • 确认验收标准并签字
  • 指定 1 名运营对接人与 1 名决策人（避免多头指挥）
放量门槛建议：对账差异 ≤ 0.5%，单渠道故障切换成功率 ≥ 99%，才进入全量。
P7

上线运营

第 10 周起 · 持续

从「搭好」变成「跑得稳、算得清」。

我方工作
  • 可用性、错误率、额度水位日常巡检
  • 用量与结算周报，模型上下架与配置调整
  • 上游改版 / 政策变更的跟进适配
  • 安全巡检：越权、伪造请求头、异常刷量
客户配合
  • 指定运营对接人，保持决策响应时效
  • 上下架与配置调整类决策需提前 1–2 天确认
  • 按月核对上游用量与本站流水

05号池方案对比

不是所有中转站都需要账号池。先判断有没有「非它不可」的独占能力。

维度 API Key 池 官网账号池
计费方式按量结算，口径透明可核账号 + 代理 IP + 补号，隐性投入高
稳定性高 官方接口有 SLA中低 封号、平台改版
合规风险低 取决于上游授权条款较高 通常违反平台条款
运维投入低（配置 + 监控）高（养号、指纹、代理、调度）
适用场景文本、标准图像、官方开放的视频模型只有官网才有的能力（部分视频 / 图片模型）
起步建议默认选它确有独占能力且客户书面确认风险后再上

号池必须做到的四个指标

  • 单号日限额：防止单个账号被打爆导致批量封禁
  • 成功率：低于 90% 说明账号质量或 IP 质量有问题
  • 平均耗时：决定下游体验与超时退款率
  • 补号量：每月封号数量，必须纳入容量规划

06风险与应对

这些是同类项目里真实踩过的坑，提前说清楚比事后解释便宜。

风险 影响 等级 应对
备案驳回或延期 上线推迟 1–4 周 高 第 1 周就启动；网站名称避敏感词；主体 / 域名 / 手机号三者一致
支付资质不足 无法在线收款 高 优先企业主体；过渡期用兑换码或对公转账

07验收标准

满足以下全部条件，才算「可上线」。

功能与计费

  • 每个上架模型都有 1 条成功真实任务，并记录上游用量
  • 本站计费结果与配置口径一致，误差为 0
  • 任务失败自动全额退款，退款日志可查
  • 支付回调幂等：重复回调不重复入账
  • 余额查询接口返回实时值，且不产生计费日志

安全与稳定性

  • 令牌只能访问授权模型，越权调用被拒
  • 伪造请求头无法绕过 IP 白名单
  • 单渠道下线后自动切换成功率 ≥ 99%
  • 数据库每日备份，可完成一次恢复演练
  • 接入文档、错误码、退款规则齐备
双方分工速查：客户负责资质、账号、决策（主体资料、云账号、上游账号与充值、上架范围与风险确认）；我方负责技术、对接、运维（备案代办、环境、网关、上游适配、号池、对账）。第三方（云厂商、支付机构、上游平台）的审核时效不受双方控制，排期时已按最坏情况预留缓冲。
本方案为实施计划参考，具体周期以实际主体资质、上游政策与调用量为准。文档中的时间区间基于同类项目经验估算，签约前可要求逐项细化。
